# Бэклог

## Правила

- Файл ведёт аналитик. Разработчик дописывает только «Разработка», статус и `[x]`. Тестировщик — только «Проверка» и статус.
- Номера:
  - фича — `F001`, `F002`, …;
  - доработка уже сданной (`[x]`) фичи — `F001.01`, `F001.02`, …;
  - пока фича не сдана, уточнение вносится в её текст;
  - номера не переиспользуются и не перенумеровываются.
- `готова к разработке` ставится, только когда заполнены цель, поведение, приёмка и границы. Если без ответа владельца исполнителю пришлось бы самому выбирать поведение, карточка остаётся `черновик`, а вопросы уходят владельцу одним списком.
- Статусы и кто их ставит — `.team/team/common.md`.

### F002. Скрипт переустановки приложения на телефон

- Статус: готова к проверке
- Родитель: —
- Приоритет: P1
- Источник: `.task/task.md`, раздел 7; владелец, 2026-11-05: «из локальной папки. Лежит в архиве артефакта рядом со скриптом»; «Модно удалять сессии»; «Скрипт, который выполняет установку, должен быть выполнен не для Shell, а для PowerShell. Это должен быть скрипт с расширением PS1. У него в начале должен быть прописан дополнительный путь для поиска ADB Tools на тот случай, если ADB Tools не прописан в переменный path в операционной системе. Скрипт должен выполняться на Windows и делать все, что было описано.»
- Изменение 2026-11-05: вместо bash-скрипта — PowerShell `.ps1` для Windows; ТЗ, раздел 7, исправлен. Владелец о поиске ADB: «Если есть указанный в переменной пас, то использовать его. Если нету, то использовать тот, который прописан в переменной в скрипте.»

#### Задача

Цель: владелец распаковывает артефакт CI на Windows и одним запуском скрипта переустанавливает приложение на подключённый телефон.

1. PowerShell-скрипт `.ps1` в корне репозитория (имя на выбор разработчика, например `install.ps1`). Работает на Windows в Windows PowerShell 5.1 (есть в Windows по умолчанию); совместимость с PowerShell 7 желательна. Запуск: правый клик → «Выполнить с помощью PowerShell» или `powershell -ExecutionPolicy Bypass -File install.ps1`; команда запуска — в комментарии в начале скрипта.
2. В самом начале скрипта — переменная с путём к папке ADB (platform-tools), с комментарием, что её можно поправить. Значение по умолчанию — `$env:LOCALAPPDATA\Android\Sdk\platform-tools` (подтверждено владельцем 2026-11-05).
3. Поиск `adb` — первый доступный по порядку: (1) системная переменная `PATH`; (2) `adb.exe` в папке из переменной скрипта. Нет ни там, ни там — сообщение: где искали, как поставить Android Platform Tools и какую переменную поправить. Скрипт пишет, какой `adb` использует и откуда.
4. Ищет APK в своей папке. Нет APK или их больше одного — сообщение об ошибке.
5. `adb devices`: ровно одно устройство в состоянии `device`. Ноль, несколько или `unauthorized` — понятное сообщение об ошибке.
6. Проверяет, установлено ли приложение (package `com.chechestor.localaichat` = `applicationId` из F001, константа в скрипте). Если установлено — удаляет (`adb uninstall`); история диалогов при этом теряется, это допустимо.
7. Ставит APK (`adb install`).
8. Выводит результат каждого шага и итог на русском: «Установка завершена успешно» или текст ошибки. Кириллица в консоли читается (файл в UTF-8 с BOM — иначе Windows PowerShell 5.1 искажает русский текст).
9. В любом исходе (успех или ошибка) ждёт нажатия клавиши, прежде чем завершиться.

#### Готово, когда

- [ ] Скрипт `.ps1` лежит в корне репозитория и попадает в артефакт F001 рядом с APK.
- [ ] В начале скрипта есть переменная с дополнительным путём к ADB.
- [ ] `adb` есть в `PATH` — используется он.
- [ ] `adb` не в `PATH`, но лежит по пути из переменной скрипта — скрипт его находит и работает.
- [ ] Запуск на Windows 10/11 в Windows PowerShell 5.1 проходит; русские сообщения читаются.
- [ ] С одним телефоном и старой версией: старая удаляется, новая ставится, видно сообщение об успехе.
- [ ] Без установленной версии: шаг удаления пропускается с сообщением, установка проходит.
- [ ] Нет устройства / два устройства / нет APK / нет `adb`: понятная ошибка, ненулевой код выхода.
- [ ] Во всех случаях окно не закрывается до нажатия клавиши.

#### Не делать

- Не скачивать APK из сети — только из своей папки.
- Не ставить поверх (`install -r`) вместо удаления — ТЗ требует удалить.

#### Разработка

Сделано (коммит `d64cfe1`):

Для типовых отказов установки есть подсказки: нет места, запрет установки по USB (Xiaomi), старый Android или чужой ABI, другая подпись.

Проверено:

Что проверить владельцу на телефоне:

1. Распаковать артефакт и проверить, что `install.ps1` лежит рядом с APK.
2. Правый клик → «Выполнить с помощью PowerShell». Со старой версией на телефоне: «Старая версия удалена» → «Установка завершена успешно». Без неё: «шаг удаления пропущен».
3. Запустить с отключённым телефоном и проверить, что сообщение понятное. Окно не закрывается до нажатия клавиши.

Риски: при политике выполнения `Restricted` контекстное меню может не запустить скрипт. Тогда запускать командой `powershell -ExecutionPolicy Bypass -File install.ps1` — она указана в начале файла. Файл из скачанного архива может быть помечен как полученный из интернета; `Bypass` это обходит.

### F003. Движок LLM: llama.cpp и Qwen3-0.6B на устройстве

- Статус: готова к проверке
- Родитель: —
- Приоритет: P1
- Источник: `.task/task.md`, разделы 2 и 5; владелец, 2026-11-05: «Размер контекста 2048ьпусть будет»; «все - ДА» (потоковый вывод, кнопка «Стоп»); «Я хочу, чтобы модель скачивалась на телефон. У телефона есть оперативная память всего 4 гигабайта. И это общий размер памяти, это не только под приложение, поэтому стоит быть экономнее. Еще у телефона есть SSD накопитель размером 32 гигабайта. Это тоже общий объем.»
- Изменение 2026-11-05: модель Qwen не зашивается в APK, а скачивается на телефон (заменяет «Зашить в apk»). Скачивание и хранение вынесены в F008; F003 — только движок.

#### Задача

Цель: приложение отвечает на русском локальной моделью без интернета.

Целевой телефон: 4 ГБ ОЗУ и 32 ГБ памяти на всё устройство, поэтому приложение экономит память.

1. llama.cpp — git-submodule `third_party/llama.cpp` на зафиксированном теге; собирается через NDK + CMake фиксированных версий под `arm64-v8a`, выполнение на CPU. Отдельный модуль `llm/` с тонким JNI-слоем.
2. Модель Qwen3-0.6B Q4_K_M (GGUF, около 0,4–0,5 ГБ) не входит в APK. Движок получает файл от F008 (дескриптор из SAF-папки). Запасной вариант: если чтение по дескриптору не работает или слишком медленное — копия GGUF во внутреннюю память, только после замера и с записью в «Разработка» (`board/decisions.md`, 2026-11-05). Для разработки до готовности F008 файл можно положить на телефон вручную (`adb push`).
3. Загрузку модели в движок делать один раз за запуск, в фоне; пока модель загружается, отправка сообщения недоступна, виден индикатор.
4. Экономия ОЗУ: модель открывается через mmap; KV-кэш на 2048 токенов (ориентир ~0,2 ГБ в f16, можно квантовать до q8); пиковое потребление процесса во время ответа — ориентир не больше 1 ГБ (замерить). Модель Vosk (F005) не держится в памяти одновременно с генерацией без необходимости.
5. Kotlin-интерфейс к движку: загрузить модель; сгенерировать ответ по списку сообщений (системное, пользователь, ассистент) с шаблоном чата Qwen; отдавать токены потоком; остановить генерацию по запросу.
6. Контекст — 2048 токенов. Как помещать в него длинную историю — F006.
7. Параметр «режим размышлений» вкл/выкл; по умолчанию выкл. При выкл — шаблон чата с `enable_thinking=false`, пустой блок `<think></think>` вырезается из ответа. Переключатель в UI — F007.
8. Генерация идёт не в главном потоке, интерфейс не зависает.

#### Готово, когда

- [ ] В авиарежиме модель из файла на телефоне загружается и отвечает на русский вопрос.
- [ ] На телефоне с 4 ГБ ОЗУ приложение не вылетает по памяти; пиковое ОЗУ, время первого токена и скорость (токенов/с) записаны в «Разработка».

- [ ] При выключенных размышлениях в ответе нет блока `<think>`.

#### Разработка

Сделано (коммиты `9c2e4a2`, `c48600b`):

- llama.cpp — submodule `third_party/llama.cpp` на теге `v0.9.0` (`cd959bae9`). NDK `29.0.14206865`, CMake `3.31.5`: эти версии уже стоят на раннере, см. `decisions.md`. Сборка только `arm64-v8a`.
- CPU-бэкенд собирается во всех вариантах ARM (`GGML_BACKEND_DL` + `GGML_CPU_ALL_VARIANTS`). При запуске ggml выбирает лучший вариант для процессора телефона (dotprod/i8mm, если есть). Библиотеки распаковываются на диск (`useLegacyPackaging`). Отключены OpenMP, KleidiAI (он скачивается во время сборки) и llamafile. Страницы 16 КБ поддержаны.
- Отступление от п. 1: вместо отдельного Gradle-модуля `llm/` код лежит в пакете `com.chechestor.localaichat.llm` модуля `app`, нативная часть — в `app/src/main/cpp/`. Вынести в модуль можно позже, поведение не меняется.
- JNI (`llm_jni.cpp`):
  - модель загружается из файлового дескриптора (`llama_model_load_from_file_ptr`) через mmap, без перепаковки весов в ОЗУ (`use_extra_bufts=false`);
  - контекст 2048, KV-кэш в q8_0 с Flash Attention (вдвое меньше f16, ~0,11 ГБ);
  - общее начало истории переиспользуется в KV-кэше, поэтому повторные вопросы в диалоге не пересчитывают всю историю;
  - ответ отдаётся кусками целых UTF-8 символов;
  - остановка через флаг и `abort_callback` прерывает и обработку промпта, и выдачу;
  - есть подсчёт токенов (для F006).
- `LlmEngine` (Kotlin):
  - один фоновый поток, загрузка один раз за запуск;

### F006. Сжатие истории под контекст 2048 токенов

- Статус: готова к проверке

- Приоритет: P2

#### Задача

Цель: длинный диалог продолжается без ошибок, модель помнит его суть.

Бюджет контекста 2048 токенов (числа — ориентиры аналитика, разработчик может уточнить по замерам и записать в «Разработка»):

| Часть | Токенов |
|---|---|
| Системный промпт (F004) | ~50 |
| Сводка старой истории | до 300 |
| Запас под ответ (максимальная длина ответа) | 512 |
| Последние сообщения целиком + новое сообщение | остальное (~1150) |

1. Перед каждой генерацией подсчитать токены токенизатором модели: системный промпт + сводка (если есть) + последние сообщения + новое сообщение + запас под ответ. Текст размышлений (F007) в историю не входит.
2. Влезает — сводка не меняется, генерация идёт сразу.
3. Не влезает — сжатие:
   - самые старые сообщения, ещё не вошедшие в сводку, отделяются так, чтобы оставшиеся последние сообщения занимали не больше ~70% своей доли (запас, чтобы не сжимать на каждом ответе);

   - если отделённые сообщения сами не влезают в один запрос — сжимать частями по очереди.
4. Сводка хранится в Room у сессии вместе с отметкой, до какого сообщения она охватывает. При повторном открытии сессии не пересчитывается.
5. Во время сжатия в диалоге вместо ответа виден индикатор «Сжимаю историю…», затем начинается ответ. «Стоп» в это время отменяет и сжатие, и ответ; прежняя сводка остаётся.
6. Новое сообщение пользователя само длиннее своей доли (~1150 токенов) — не отправляется, сообщение «Сообщение слишком длинное, сократите его».
7. В базе история хранится полностью; сжатие влияет только на то, что уходит в модель. Пользователь сводку не видит.

Что проверить владельцу на телефоне:

1. Поставить APK через `install.ps1`. Виден экран «Выберите папку для моделей» → «Выбрать папку» → Download → создать `LocalAIChat` → «Использовать эту папку» → «Разрешить».
2. Выбрать другую папку (например, сам `Download`) — снова экран выбора с текстом про нужную папку.
3. На мобильной сети без Wi-Fi: кнопка неактивна, «Подключитесь к Wi-Fi».
4. По Wi-Fi «Скачать и установить» (разрешить уведомления): прогресс в приложении и в шторке. Посреди загрузки выключить Wi-Fi — «на паузе»; включить — загрузка продолжается, а не начинается заново. После загрузки — «Проверка…» → экран проверки модели, модель загружается и отвечает.
5. Переустановить скриптом `install.ps1` → выбрать ту же папку → «Проверка моделей…» (~10–30 с) → приложение без повторного скачивания. Повторный запуск — папку не спрашивает, проверка мгновенная.
6. «Удалить и скачать заново» → подтвердить → экран установки; в `Download/LocalAIChat` файлов моделей нет.
7. Подмена: через проводник ПК обрезать или заменить `Qwen3-0.6B-Q4_K_M.gguf` (после переустановки) → проверка находит, предлагается скачать заново.

Риски:

- Чтение GGUF через дескриптор SAF (FUSE) не проверено на устройстве. Если загрузка медленная или не работает — запасной вариант с копией (decisions.md).
- Задача не стартует на сетях без лимита трафика, которые не Wi-Fi (Ethernet): она завершается повтором до появления Wi-Fi.
- На Android 15 у foreground service `dataSync` лимит 6 ч в сутки — для ~0,44 ГБ достаточно.
