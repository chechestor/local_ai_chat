# Общие правила команды

Читается первым всеми агентами.

## Владелец и общение

- Владелец — **chechestor**. Ставит задачи, принимает решения, проверяет результат в `main`.
- С владельцем общаемся по-русски.
- Внешние тексты (UI приложения, README для пользователей, описания релизов) пишем на русском, регион — RU. Это следует из ТЗ: диалог с моделью на русском. Если понадобится английская версия, рядом даётся перевод для владельца.
- Сначала спросить, если ошибка стоит дорого: переписывание истории git, удаление, публикация, деньги, обещание вовне.
- Если ошибка дёшево исправляется — сделать разумно и явно назвать допущение.

## Источники правды (по убыванию)

1. Прямое слово владельца в текущем разговоре.
2. `notes.md` своей роли и `board/decisions.md`.
3. Карточка в `board/backlog.md`.
4. Спецификации проекта: `.task/task.md`.
5. Код и тесты — как факт того, что реально работает.

Не обещать того, чего нет в коде.

## Задачи и статусы

| Статус | Кто ставит | Что значит |
|---|---|---|
| `черновик` | продакт, аналитик | Идея, ещё не описана |
| `готова к разработке` | аналитик | Есть цель, поведение, приёмка и границы |
| `в работе` | исполнитель | Взята в работу |
| `готова к проверке` | исполнитель | Сделано, ждёт проверки |
| `блокер` | любой | Не проходит проверку или нужна информация; причина в карточке |
| `готова` | тестировщик (пока его нет — владелец) | Проверка пройдена |

- Галочку `[x]` в «Списке задач» ставит исполнитель сразу после разработки, вместе со статусом `готова к проверке`.
- Тестирование галочку не ставит и не снимает.
- Если в ответе владельцу задача без галочки, она не сдана.
- Из `черновика` код не пишут.

## Git и среды

| Среда | Где | Ветка | Кто деплоит |
|---|---|---|---|
| local | ПК разработчика + Android-эмулятор | `main` | разработчик |
| device | подключённый по USB Android-телефон (ARM64) | `main` | скрипт установки, владелец |
| CI | GitHub Actions — сборка APK | `main` | CI |
| staging / prod | нет (пилот, приложение локальное) | — | — |

Проект экспериментальный, поэтому ветка одна — `main`. Других веток и PR нет (`board/decisions.md`, 2026-11-05).

- Коммит и push — прямо в `main`, когда это входит в задачу роли или владелец попросил. Отдельного «пушь» не нужно.
- Перед push — подтянуть свежий `main` (`git pull --rebase`). Тесты, линтер и проверка типов должны проходить.
- Только с явного «да» владельца в том же разговоре: `push --force`, переписывание истории (rebase/amend уже запушенного, reset), удаление веток и тегов, создание новых веток.
- Разрушительные действия — только по явной просьбе в том же разговоре.
- Сообщение коммита — одна фраза: что изменилось и зачем, номер задачи в скобках. Пример: `Add chat list screen with session deletion (F003)`.

## Секреты

- Пароли, токены, ключи подписи APK, учётки хранятся только в `.team/local/` (не в git) и в GitHub Secrets.
- В notes, бэклог, коммиты, логи и скриншоты они не попадают.
- Агенты секреты не вводят и не печатают. В GitHub Secrets и подобные места их вносит владелец.

## Кто куда пишет

- Любая роль может менять любые файлы в `.team/` без запроса владельцу и оркестратору (владелец, 2026-11-05).
- Свои заметки роль ведёт в `.team/team/<role>/`, черновики — в `scratch/` внутри неё (не в git).
- Код и инфраструктуру меняют только разработчик и CI/CD.
- Чужие файлы ролей при необходимости правят, но смысл чужих записей не меняют; о правке пишут в отчёте.
- `board/decisions.md` дописывают все, ничего не стирают.
- `board/backlog.md` правят по правилам из шапки этого файла.
- Спецификации (`.task/`) правятся только по просьбе владельца.

## notes.md — память роли

- Записывать сразу, в той же сессии, как только владелец что-то уточнил или решил.
- Формат: `- ГГГГ-ММ-ДД, владелец: <что решено>`. Одна мысль — одна строка.
- Разделы: «Договорённости», «Грабли», «Открытые вопросы владельцу», «Ссылки».
- Устаревшее не удалять молча: исправить и указать дату.
- То, что касается всей команды, записывается в `board/decisions.md`, а в notes ставится ссылка.

## Как сдавать работу

Короткий отчёт владельцу:

1. Что сделано (1–3 строки) и где результат: путь, URL, номер задачи, коммит.
2. Что не сделано или под вопросом.
3. Принятые допущения.
4. Следующий шаг.

Без пересказа всех шагов.
