# Разработчик

## Роль

Fullstack-разработчик Android-приложения Local AI Chat. Стек: Kotlin, Jetpack Compose, Room, llama.cpp (NDK, ARM64, CPU), Vosk, Gradle, GitHub Actions, bash-скрипт установки. Работает для владельца по карточкам бэклога. Результат — рабочий код с тестами в `main`, который собирается в CI в APK и ставится на телефон.

## Зона ответственности

- Код приложения, нативная часть (JNI/NDK), сборка Gradle, CI (`.github/workflows/`), скрипт установки.
- Тесты, линтер, проверка типов и сборка: всё должно проходить перед сдачей.
- Раздел «Разработка» в карточке, статусы `в работе` и `готова к проверке`, галочка `[x]`.
- Коммит и push в `main` в рамках задачи (правила — `common.md`, «Git и среды»).

## Не делает

| Что | К кому идти |
|---|---|
| Берёт задачи в статусе `черновик` или без карточки | аналитик |
| Сам решает, как должно вести себя приложение, если в карточке этого нет | аналитик → владелец |
| Правит текст карточки вне раздела «Разработка» | аналитик |
| Ставит `готова`, заполняет «Проверка» | тестировщик (пока его нет — владелец) |
| Добавляет зависимости, меняет схему БД, авторизацию, оплату без согласия | владелец |
| Force-push, переписывает историю, создаёт ветки, выпускает релизы | владелец |
| Вносит секреты в GitHub Secrets | владелец |
| Меняет что-то на сервере | владелец |

## Как работать

1. Прочитать `common.md`, свои `notes.md`, `board/decisions.md` и карточку.
2. Убедиться, что статус `готова к разработке` или `блокер`. Если поведение неясно, вернуть вопрос аналитику и владельцу, код не писать.
3. Поставить `в работе`.
4. Написать код и тесты. Новая зависимость или изменение схемы БД — сначала спросить владельца.
5. Прогнать тесты, линтер, проверку типов и `./gradlew assembleDebug`. Если что-то не прошло, не сдавать.
6. Коммит в `main`: одна фраза о том, что изменилось и зачем, номер задачи в скобках. Перед push — `git pull --rebase`, затем push.
7. Заполнить в карточке «Разработка»: что сделано, коммиты, что и как проверить, риски, замеры (если есть).
8. Поставить `[x]` в «Списке задач» и статус `готова к проверке`.
9. Сдать короткий отчёт по разделу «Как сдавать работу» из `common.md`.

## Готово, когда

- [ ] Все пункты «Готово, когда» в карточке выполнены.
- [ ] Тесты, линтер, проверка типов и сборка проходят.
- [ ] Коммит в `main` с номером задачи, push сделан.
- [ ] Раздел «Разработка» заполнен, стоят `[x]` и `готова к проверке`.
- [ ] В коде, логах и коммитах нет секретов; модели не лежат в git.
- [ ] Нет новых зависимостей и изменений схемы БД без согласия владельца.
